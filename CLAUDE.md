- Board = 241.95×121.15×0.776 mm; board top face Z=0, bottom Z=−0.78. Side from placement Z sign. Top-side height = z1−0; bottom-side protrusion = −0.78−z0.
- ⚠️ **~995/3924 components carry a 3.81 mm (0.15") placeholder height** (Allegro default for parts with no real 3D model — all `CTK0_SM*` named). Must substitute by package or exclude, else thousands of false height violations.

**2026-09-28 (cont.): DXF diff now aligns the two revisions before comparing.**
- **Why**: the diff renders both revisions in the same sheet window at 3 px/mm with a 1 px tolerance, so a global coordinate drift of **>0.33 mm** turns every stroke into a red+green pair (77 change regions on a test pair that really only had one edit). The old code explicitly assumed both revisions shared the sheet coordinate system.
- **Estimator** (`analysis/diff_align.py`, importable + CLI): screw-hole (`CIRCLE`) centres bucketed by radius → all pairwise Δ voted in 0.1 mm bins → median of the winning bin. Vector coordinates, so there is **no pixel error** (an image-correlation approach is limited to 0.33 mm here); `LINE` midpoints bucketed by length+angle give an independent cross-check. Consensus % (A-features that find a match after the shift) is the trust metric; outlier features are the "what changed" clue. `estimate_multi` = sequential RANSAC (vote → drop inliers → vote again) finds a **second** offset, which is how "one view got dragged during drafting" is detected without knowing the view boxes.
- **Validated against ground truth** (only one real revision exists, so `analysis/make_rev.py` derives controlled ones from it): identical files → (0.000, 0.000)/100%; pure shift (+2.35, −0.80) → recovered exactly, 100%; shift + 1343 entities deleted → **still exact**, consensus 97.9%, and the 11 outlier holes cluster inside the deleted window; only-TOP-view moved → global (0,0)/78.3% + second model (+1.000, +0.500) with 21.7% of features spanning (71.1, 459.7)–(304.2, 575.4) mm ≈ the TOP_LIMIT view box.
- **Effect on the diff** (same pair, alignment off → on): change regions **77 → 8**, changed pixels **102,217/100,636 → 1,240/0** (the fixture only deleted things, so "added 0" is correct).
- **Policy**: apply only when consensus ≥95% **and** the line cross-check agrees within 0.1 mm; zero offset with high consensus = `already_aligned`; otherwise `low_consensus` and it **refuses to align** (never silently absorbs real changes) and reports the per-offset breakdown + a hint. Per-region offsets are reported, never auto-applied — elastic alignment would align the changes away.
- **Plumbing**: `cmd_diff` gained `--no-align` / `--align-dx/--align-dy`, writes `align{applied,dx,dy,consensusPct,crossCheckMm,outliers,reason,models,regions,suggest,hint}` into `diff.json`; `cmd_diffzoom` takes the same offset (and tags the cached filename with it, so different alignments don't collide); `POST /api/dxfdiff` accepts `noAlign`, new **`POST /api/dxfdiff/:id/realign`** re-runs the same pair with a chosen offset (or none); the zoom route reuses whatever alignment was applied. UI: 「不要自動對齊」 on the form, an align panel (offset, consensus %, cross-check, outlier count, multi-offset list with 「用這個位移重新比對」), and a 「疊圖微調」 mode (both revisions stacked with `difference` blending, arrow keys 0.1 mm / Shift 1 mm, then 「用這個位移重新比對」).
- **Known-open**: per-view *application* is manual (pick the reported offset); rotation/scale differences are not estimated (translation only); a real Creo re-export may carry ~0.001 mm rounding noise, so the 0.05 mm consensus tolerance may need loosening once a genuine second revision exists.
